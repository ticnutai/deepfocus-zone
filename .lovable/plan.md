## מטרה

היום רק "אורח" שואב את השאלות/קטגוריות מהמשתמש-המקור שהגדרת. אנחנו רוצים שגם **משתמש רשום** יראה את אותו מאגר שאלות מהמקור (read-only), אבל הסטטיסטיקות/תקדמות/כרטיסים שהוא יוסיף — יישמרו לחשבון שלו בענן (read/write רגיל). הכל ייחתך לפי המטריצה של הפרופיל/תפקיד שלו.

## איך זה יעבוד

```text
┌──────────────────────────┐
│ User logs in (auth)      │
└─────────────┬────────────┘
              │
   ┌──────────┴──────────┐
   │ Cloud reads          │
   │  • own cards/cats    │
   │  • source cards/cats │ ← merged, source marked readOnly
   │  (matrix filter)     │
   └──────────┬──────────┘
              │
   ┌──────────┴──────────┐
   │ Cloud writes         │
   │  • only to own user  │
   │  • blocked on source │
   └─────────────────────┘
```

## שינויים מתוכננים

### 1) מסד הנתונים
- RPC חדשה `get_source_overlay_snapshot()` — זהה ל-`get_guest_bootstrap_snapshot` אבל זמינה ל-`authenticated` (לא רק `anon`).
- RPC חדשה `get_source_category_children(parent_id)` — מקבילה ל-guest.
- RPC חדשה `get_source_unreviewed_cards_page(...)` ו-`get_source_card_categories()`.
- כולן `SECURITY DEFINER`, קוראות את `guest_source` site-setting כדי לדעת מהו ה-user_id של המקור.
- מתג חדש ב-site-setting: `source_overlay_for_users` (boolean) — האדמין יכול לכבות בלי לכבות את האורח.

### 2) שכבת הסטור (`src/lib/study/store.ts`)
- בעת bootstrap למשתמש רשום: שולפים גם snapshot של המקור (אם המתג דלוק).
- מיזוג: כל פריט שמגיע מהמקור מסומן `__source: true` ו-`__readOnly: true`. ב-conflict-id, מידע מקומי גובר.
- כל פעולת `update/delete/setSrs` בודקת `__source/__readOnly` — אם כן, נחסמת בענן (אפשר fork ל-own copy בלחיצה).
- lazy load (children/unreviewed pages) מעדיף את ה-RPC הרגילה לעצמו ומבצעת קריאה נוספת לאוברליי של המקור.

### 3) סינון מטריצה
- המטריצה כבר מוגדרת ב-`sidebarConfig`/`matrix` של הפרופיל. נחיל את אותו פילטר על הפריטים שמגיעים מהמקור (אותו קוד שעובד היום באורח).

### 4) ממשק אדמין (`GuestProfilesTab`)
- כרטיס "מקור ענן" הקיים יקבל שני מתגים נפרדים:
  - **אורח קורא מהמקור** (כיום קיים)
  - **משתמשים רשומים קוראים מהמקור** (חדש)
- בורר משתמש-המקור משותף לשניהם (כבר תומך בכל משתמש, לא רק אדמין).

## מה לא משתנה

- RLS על כל הטבלאות נשאר זהה — משתמשים רשומים לא ייגעו ישירות בנתוני המקור, אלא רק דרך ה-RPCs.
- כל write של משתמש רשום ממשיך ללכת לחשבון שלו (RLS `user_id = auth.uid()`).
- ה-IndexedDB המקומי לא משמש פה — הכל בענן של המשתמש עצמו.
