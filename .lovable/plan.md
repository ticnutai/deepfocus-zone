## מה משתנה

ב‑`src/components/admin/RoleDefaultsTab.tsx`, בלשונית "טאב חסימה" → קטע "מקטעי סיידבר":

### 1. תצוגה זהה לסיידבר
- במקום grid של 2–3 עמודות עם תוויות יבשות, נציג רשימה אנכית שמשחזרת את תבנית הסיידבר האמיתי:
  - אותו סדר ושמות מ‑`DEFAULT_SIDEBAR_ITEMS` (כולל אייקונים).
  - כל שורה: כפתור בסגנון פריט סיידבר (rounded-xl, ריווח זהה, label בצד ימין, עיגול אייקון gold מצד שמאל) — מועתק מסגנון `NavList` שב‑`AppSidebar.tsx`.
  - כשהפריט "פתוח" — סגנון רגיל. כשהוא "חסום" — אופסיטי מעומעם + קו חוצה (`line-through`) + tag אדום קטן "חסום".
- בראש הקטע יישאר כפתור "בחר הכל / נקה הכל" אבל בנוסח חדש: "פתח הכל" / "חסום הכל" (כדי להתאים להיגיון החדש של המתג).

### 2. הפיכת המתג
- `Switch` יקבל `checked={!blocked}` (דלוק = פתוח, כבוי = חסום).
- ה‑`onCheckedChange` ימשיך לקרוא ל‑`toggleSection(s.id)` כמו היום (האחסון נשאר אותו דבר — רשימת ids חסומים).
- התווית ליד המתג: "פתוח" כשדלוק (ירוק/muted), "חסום" כשכבוי (אדום).
- טקסט העזר "חסום = פעיל, פתוח = כבוי" יוחלף ל‑"דלוק = פתוח למשתמש, כבוי = חסום".

### 3. שינוי תואם בקטע "וידג'טים"
- אותה הפיכת מתג + תוויות (`checked={!blocked}`, "פתוח"/"חסום") כדי לשמור על עקביות. התצוגה נשארת grid כמו היום (לא ביקשת לשנות וידג'טים לתבנית סיידבר).

## מה לא משתנה

- מבנה הנתונים הנשמר (`blocklist.sections` / `blocklist.widgets`) — עדיין רשימת ה‑ids ה**חסומים**.
- לוגיקת אכיפת החסימה ב‑`AppSidebar`/`featureBlocklist` — לא נגענו.
- שאר הלשוניות (פריסה, שיוכים, פרופילים) — בלי שינוי.
