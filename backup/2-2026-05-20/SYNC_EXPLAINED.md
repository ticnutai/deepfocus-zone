## 🏠 קודם כל — מה זה בכלל?

דמיין שיש לך שני מקומות שמאחסנים את הכרטיסיות שלך:

```
┌─────────────────────────────┐      ┌─────────────────────────────┐
│  📱  הדפדפן שלך             │      │  ☁️  הענן (Supabase)         │
│                             │      │                             │
│  IndexedDB                  │      │  מסד נתונים PostgreSQL       │
│  (כמו מחברת על השולחן)      │◄────►│  (כמו ספריה ראשית)          │
│                             │      │                             │
│  מהיר, עובד בלי אינטרנט    │      │  גיבוי, ניגשים מכל מקום    │
└─────────────────────────────┘      └─────────────────────────────┘
```

> 💡 **אנלוגיה:** הדפדפן = דף טיוטה על השולחן. הענן = הספר המסודר בספרייה.
> תמיד עובדים עם הטיוטה, ומדי פעם מעדכנים את הספר בספרייה.

## 🗑️ מקרה 5 — מה קורה כשמוחקים כרטיסיות/קטגוריות?

### כרטיסיות — מחיקה ישירה

```
משתמש מוחק כרטיסייה
         │
         ▼
┌────────────────────────┐
│ הוסרה מה-IndexedDB     │
└────────────────────────┘
         │
         ▼
┌────────────────────────┐
│ bg(supabase.delete())  │
│ ← מחיקה ישירה מהענן   │
└────────────────────────┘
```

### קטגוריות — מחיקה "רכה" (Soft Delete)

קטגוריות לא נמחקות ממש מהענן — הן **מסומנות כמחוקות** עם תאריך.
למה? כדי שמכשיר שני יידע שמחקנו אותן ולא "יחיה" אותן מחדש.

```
משתמש מוחק קטגוריה
         │
         ▼
┌────────────────────────────────────┐
│ 1. הוסרה מה-IndexedDB              │
└────────────────────────────────────┘
         │
         ▼
┌────────────────────────────────────┐
│ 2. נכנסת לתור מחיקות (IDB)        │
│    enqueue pendingDelete           │
└────────────────────────────────────┘
         │
         ▼
┌────────────────────────────────────┐
│ 3. flushPendingDeletes()           │
│    UPDATE categories               │
│    SET deleted_at = now()          │
│    WHERE id = 'abc-123'            │
│                                    │
│    ← לא DELETE! רק מסמן           │
└────────────────────────────────────┘
         │
         ▼
┌────────────────────────────────────┐
│ טעינה עתידית מהענן:                │
│ WHERE deleted_at IS NULL           │
│ ← קטגוריה מחוקה לא תחזור לעולם! │
└────────────────────────────────────┘
```

## 🛡️ מקרה 6 — "שומר הבטיחות" (95% Rule)

**הבעיה:** מה אם הדפדפן טען רק 2000 כרטיסיות מתוך 10000 (כי נפסקה הטעינה)?
האם הסנכרון ימחק מהענן את 8000 שלא נטענו?

```
┌─────────────────────────────────────────────────────┐
│ בענן: 10,000 כרטיסיות                               │
│ מקומית: 2,000 כרטיסיות (טעינה נפסקה)              │
└─────────────────────────────────────────────────────┘
                        │
                        ▼
         ┌──────────────────────────────┐
         │ בדיקת בטיחות:                │
         │                              │
         │ local (2000) ≥ remote (10000)│
         │         × 0.95              │
         │                              │
         │  2000 ≥ 9500 ?              │
         │       ❌ לא!                 │
         └──────────────────────────────┘
                        │
                        ▼
         ┌──────────────────────────────┐
         │ 🛑 מסרב למחוק!               │
         │                              │
         │ console.warn:                │
         │ "Skipping delete of 8000     │
         │  remote cards:               │
         │  local=2000 remote=10000     │
         │  (incomplete load guard)"    │
         └──────────────────────────────┘
                        │
                        ▼
         ┌──────────────────────────────┐
         │ ✅ שום דבר לא נמחק          │
         │ הנתונים בענן שלמים           │
         └──────────────────────────────┘
```

**מתי כן מותר למחוק?**
```
✅ מותר: local ≥ 95% מהענן (טעינה כמעט שלמה)
✅ מותר: פחות מ-200 רשומות בענן (קטן = שלם בוודאות)
❌ אסור: local < 95% מהענן (כנראה הטעינה נחתכה)
```

## 🔑 מקרה 7 — כפילויות? UUID מונע הכל!

```
┌─────────────────────────────────────────────────────┐
│ כל כרטיסייה מקבלת UUID בעת יצירתה:                │
│                                                     │
│  id = crypto.randomUUID()                          │
│     = "f7a3b2c1-4d5e-6f7a-8b9c-0d1e2f3a4b5c"     │
│                                                     │
│ ה-UUID הזה:                                        │
│  ✅ לעולם לא משתנה                                  │
│  ✅ ייחודי בעולם כולו (הסתברות לכפילות = 0)        │
│  ✅ נשמר ב-IndexedDB ועובר לענן                    │
└─────────────────────────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────┐
│ כתיבה לענן תמיד עם:                                │
│ upsert(card, { onConflict: "id" })                 │
│                                                     │
│ הענן שואל:                                         │
│  "יש כבר שורה עם id='f7a3b2c1...'?"                │
│                                                     │
│   ✅ כן → UPDATE (מעדכן)                            │
│   ✅ לא → INSERT (מוסיף)                            │
│   ❌ אף פעם → שתי שורות לאותה כרטיסייה             │
└─────────────────────────────────────────────────────┘
```

## 🆕 מקרה 10 — כניסה מדפדפן חדש (ענן מלא, IDB ריק)

זה הפחד הגדול: "הדפדפן יראה שה-IDB ריק ויסמן הכל כ'יש למחוק'!"

```
          ❌ איך זה לא עובד (הפחד)
          ─────────────────────────
          IDB ריק → sync → "אין כרטיסיות!"
                        → מוחק הכל מהענן!

          ✅ איך זה באמת עובד
          ─────────────────────────
          IDB ריק
            │
            ▼
          loadAll() ← שולף מהענן
            │
            ▼
          memState = כל הנתונים מהענן
            │
            ▼
          שמירה ל-IDB
            │
            ▼
          existingJobs = [] (ריק)
            │
            ▼
          runPendingCloudSync ← לא רץ!
            │
            ▼
          ✅ הכל תקין, לא נמחק שום דבר
```

> 🔐 **הסיבה:** `syncRowsById` (שמוחק) רץ **רק** בתוך `runPendingCloudSync`.
> `runPendingCloudSync` רץ **רק** כשיש `sync jobs` בתור.
> דפדפן חדש = תור ריק = אפס מחיקות.

## 📊 טבלת סיכום — מי מנצח במצב קונפליקט?

| מצב | מי מנצח |
|-----|---------|
| אותה כרטיסייה עודכנה ב-2 מכשירים | ה-`updated_at` המאוחר יותר (LWW) |
| כרטיסייה חדשה עם UUID קיים | עדכון (UPDATE), לא כפילות |
| קטגוריה נמחקה מקומית | נשמרת עם `deleted_at` בענן |
| IDB ריק + ענן מלא | ענן מנצח (הכל נטען) |
| IDB מלא + ענן עם פחות נתונים | safety guard מונע מחיקה בטעות |
| כשלון רשת | תור ב-IDB, מנסה שוב אוטומטית |
