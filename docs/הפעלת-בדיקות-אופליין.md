# בדיקות קבועות להרשמה וסנכרון אופליין

## הפעלה

בתיקיית הפרויקט הפעילו `npm run test:offline-sync`.

בסוף מופיע סיכום הצלחות וכישלונות. בנוסף נשמר דוח JSON ב־`.codex-runtime/offline-sync-results.json`. קוד יציאה שאינו אפס מציין כישלון ומאפשר לעצור תהליך שחרור אוטומטי. הבדיקות כלולות גם ב־`npm test` הכללי.

## בטיחות

השרת ותור הנתונים מדומים באמצעות mocks. אין צורך בסיסמה אמיתית, אין יצירת חשבונות ואין כתיבה לענן. כל בדיקה מתחילה עם אחסון מקומי מדומה נקי. אין להשתמש בחשבון אישי במקום סביבת בדיקות.

## התרחישים

- הרשמה במצב מנותק, אימות סיסמה מקומי ודחיית סיסמה שגויה.
- חזרת חיבור ושיוך תמונת הנתונים לחשבון המאומת.
- דחיית הרשמה ושמירת המצב הממתין.
- כשל כתיבה לתור ואפשרות ניסיון חוזר.
- החלפת חשבון בזמן הרשמה ובזמן התחברות מחדש.
- ביטול פעולה עקב יציאה מהחשבון.
- דחיית מזהה משתמש שאינו תואם בשלב ההתחברות האחרון.
- הרשאות אופליין, מעבר לאורח וחזרה לנתיב מקומי בטוח.

## מה הבדיקות אינן מוכיחות

זהו מערך regression מקומי, לא בדיקה מול Supabase אמיתי. הוא אינו מדמה באופן מלא אירועי session מקבילים של SDK אמיתי או את מנגנון IndexedDB הפיזי. לפני שחרור עם הבטחת סנכרון בין מכשירים יש להשתמש בפרויקט ענן לבדיקות ובשני הקשרים מבודדים: ליצור חשבון בדיקה, להוסיף שאלה באופליין, לחבר, לוודא את הרשומה בשרת ולקרוא אותה מההקשר השני. יש לבדוק גם אימות מייל, ניתוק באמצע והחלפת זהות בזמן מסירת session. אין להכריז על בדיקות אלו כעוברות בלי שהורצו.
